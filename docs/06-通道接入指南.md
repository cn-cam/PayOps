# 通道接入指南

每个支付类型需要填写的凭证、回调地址配置位置、客户端配合点与实现依据。配置表单由后端元数据驱动，在后台"通道管理 → 新增通道"选择类型后即可看到同样的字段。

- 通道的上游回调地址：`{PublicBaseUrl}/api/notify/{provider}/{通道ID}`（后台通道列表可一键复制）。
- **验证状态**：下表的"单元测试"指用测试内生成的密钥验证签名/验签/解析逻辑自洽；所有真实类型**均未使用真实商户凭证联调**，首次上线前必须逐个通道走通真实交易。

| 类型 | 支付方式 | 查单 | 关单 | 接口退款 | 凭证核验 | 订阅 | 对账单 | 单元测试覆盖 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 微信支付 `wechat` | APP / JSAPI / Native / H5 | ✔ | ✔ | ✔ | - | - | ✔ | 请求签名、回调验签 + AES-GCM 解密、账单解析 |
| 支付宝 `alipay` | APP / 手机网站 / 电脑网站 / 扫码 | ✔ | ✔ | ✔ | - | - | ✔ | 下单签名、回调验签、账单 zip(GBK) 解析 |
| 抖音支付 `douyin` | APP / H5 / PC 扫码 | ✔ | ✔ | ✔ | - | - | ✔ | 请求签名、APP 调起签名、支付/退款回调验签解密、账单解析 |

## 微信支付（APIv3，直连商户）

| 字段 | 来源 |
| --- | --- |
| AppID | 与商户号绑定的开放平台移动应用 / 公众号 / 小程序 AppID |
| 商户号、商户 API 证书序列号、商户 API 私钥（apiclient_key.pem） | 商户平台 → API 安全 |
| APIv3 密钥 | 商户平台 → API 安全（32 位） |
| 微信支付公钥 / 平台证书（PEM）+ 公钥 ID | 商户平台 → API 安全。新商户使用"微信支付公钥"并填写 `PUB_KEY_ID_…` |

- 回调地址下单时自动携带，无需在商户平台配置；退款回调为 `…/refund`。
- 同一商户号绑定了多个 AppID 时，为每个 AppID 建一个通道。
- 一个渠道绑定多个微信商户号即可实现权重分流 / 容灾。

## 支付宝（公钥模式，RSA2）

应用 AppID、应用私钥、支付宝公钥（开放平台"接口加签方式"里查看的**支付宝公钥**，不是应用公钥）。网关默认正式环境，沙箱改为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`。证书模式未实现。

## 抖音支付（商家平台，APP / H5 / PC 扫码）

对应抖音支付商家平台（pay.douyinpay.com）的直连商户产品：App 支付、H5 支付、Native 支付（PC 扫码）。

| 字段 | 来源 |
| --- | --- |
| 应用 AppID | 抖音开放平台应用。**APP 支付用移动应用 AppID，H5 / PC 扫码用网站应用 AppID**，两类请各建一个通道，并在绑定里用"支付方式"限定 |
| 直连商户号 | 商家平台下发 |
| 商户 API 证书序列号、商户 API 私钥 | 商家平台【产品中心 → 密钥管理 → 接口加签证书】 |
| 接口加密密钥 | 32 位对称密钥（回调与平台证书解密）。未设置时抖音可能不发送回调 |
| 抖音支付平台证书（可选） | PEM。留空则自动调用平台证书接口获取并缓存，证书轮换时自动跟随 |

| 支付方式 | 说明 |
| --- | --- |
| `douyin_app` | 返回 `appid / partnerid / prepayid / package(Sign=DYPay) / noncestr / timestamp / sign`，传给抖音支付 OpenSDK |
| `douyin_h5` | 返回跳转 `url`（5 分钟有效）。发起跳转的页面域名必须是已配置的 H5 支付域名；传了 `returnUrl` 会自动拼到 `return_url` |
| `douyin_pc` | 返回二维码 `codeUrl`，**2 分钟有效**；过期后用相同 `mchOrderNo` 重新下单即可刷新二维码 |

- 回调地址下单/退款时自动携带（须 HTTPS、不带参数）；支付回调与退款回调共用通道回调地址（退款为 `…/refund`）。
- 与微信 APIv3 的主要差异（均已按抖音文档实现）：认证方案 `DouyinPay-RSA`、响应头前缀 `Douyinpay-`、验签只有平台证书模式、关单成功为 HTTP 200、退款查询必须带 `mchid`、退款请求必须带 `mchid` 与 `currency`。
- 对账：`GET /v1/bill/billapply`（`bill_type=TRADE`、`tar_type=GZIP`）。账单编码官方说法不一（UTF-8 / GBK），实现为先按 UTF-8 严格解码、失败回退 GBK。
- 尚未确认的细节：账单下载地址是否需要签名（实现里带了签名）、平台证书接口解密后的明文格式（按 PEM 处理，兼容裸 Base64）。

## 抖音小程序（担保支付 ecpay）

小程序 AppID、支付 SALT（请求签名）、回调 Token（回调验签，二者不同）。回调地址下单时携带，建议同时在小程序后台"支付设置"填写作为兜底（需 HTTPS 443）。支付方式 `douyinmp_ecpay`。

> 抖音已将担保支付限定在生活服务类小程序，其余新接入小程序需使用"通用交易系统"（`tt.requestOrder` + RSA 签名），当前未实现。
## 华为应用内支付（HMS Core IAP）

| 字段 | 来源 |
| --- | --- |
| 应用 AppID / 应用密钥 | AppGallery Connect → 项目设置（OAuth 客户端） |
| IAP 公钥 | AppGallery Connect → 应用内支付服务 |

1. 业务下单（`huawei_iap`，带 `productId`）→ 返回 `developerPayload`；
2. 客户端 `createPurchaseIntent` 时把 `developerPayload` 原样传入；
3. 支付完成后客户端把 `purchaseToken` 交给业务服务端 → `POST /api/pay/orders/verify`；
4. 把通道回调地址配置到"订单关键事件通知"（v2）。通知本身无签名，本系统只把它当触发器并回源核验。

发货后由客户端或业务服务端调用华为的消耗接口（本系统不代为消耗）。

**订阅**：下单带 `subscribe: true`；核验时除 `purchaseToken` 外还要提交客户端 `InAppPurchaseData` 里的 `subscriptionId`。续订、停止续订、恢复续订、撤销由"关键事件通知 v2"的订阅事件驱动（通知先验签，再回源查询订阅接口取权威数据）；华为没有到期通知，到期由巡检查询确认。支持服务端退订（停止订阅，不退款）。通道配置里的"Subscription 服务地址"中国站保持默认。

## 荣耀应用内支付

应用 AppID、应用密钥、IAP 公钥（荣耀开发者服务平台）。流程同华为：下单返回 `bizOrderNo` / `developerPayload`，客户端传入 SDK；支付后提交 `purchaseToken` 核验；回调地址配置到"支付结果回调"。荣耀建议不要用实付金额比对（优惠券场景），本系统对荣耀不做金额校验，以签名的购买数据 + 订单绑定为准。

**订阅**：荣耀的订阅型商品需单独申请开通，订阅标识为合约号 `agreementNo`。回调事件 2002（订阅首购）、2003（续费）、2004（升级）按扣款成功处理，2001（解约）按退订处理；支持服务端解约。荣耀没有"恢复续订""到期"事件，到期由巡检查询确认。以下细节官方未说明、需联调确认：续费回调是否带独立订单号、解约后权益是否保留到周期结束、自动扣款失败是否会发 2001。

## 苹果应用内购买（StoreKit 2）

| 字段 | 来源 |
| --- | --- |
| Bundle ID | 应用包名 |
| Issuer ID、密钥 ID、API 私钥（.p8） | App Store Connect → 用户和访问 → 集成 → App 内购买项目 |
| 环境 | 自动 / 仅正式 / 仅沙盒。**正式通道选"仅正式"**，避免沙盒凭证在生产发货 |

1. 业务下单（`apple_iap`，带 `productId`）→ 返回 `appAccountToken`（由订单号可逆编码的 UUID）；
2. 客户端 `product.purchase(options: [.appAccountToken(UUID(uuidString: token)!)])`；
3. 支付完成后把 `transaction.id`（或 `jwsRepresentation`）交给业务服务端 → `verify`；本系统调用 App Store Server API 取回签名交易并校验证书链（锚定 Apple Root CA - G3）；
4. 把通道回调地址配置到"App Store 服务器通知"（Version 2）。`ONE_TIME_CHARGE` 入账，`REFUND` 生成 `source=upstream` 的退款并通知业务回收权益。

苹果价格由商品档位决定，本系统对苹果不做金额校验（以商品 ID + 订单绑定为准）；`amount` 请传该档位的人民币标价用于统计。

**订阅**：下单带 `subscribe: true`，其余与一次性商品相同。订阅标识为 `originalTransactionId`，每期扣款是一笔新的 `transactionId`。服务器通知的处理：`SUBSCRIBED` / `DID_RENEW` → 扣款成功（首购或续费单）；`DID_CHANGE_RENEWAL_STATUS` → 退订 / 恢复续订；`EXPIRED` / `GRACE_PERIOD_EXPIRED` → 到期；`REFUND` → 对应那一期订单生成上游退款，若退的是当前周期则订阅撤销；`REVOKE` → 撤销。到期巡检调用 Get All Subscription Statuses 确认。**苹果没有服务端退订接口**，只能在 App 内调用 `AppStore.showManageSubscriptions` 或引导用户到系统设置退订。升降级（`DID_CHANGE_RENEWAL_PREF`）等事件目前忽略。

## OPPO

无需凭证（验签使用 OPPO 官方统一公钥，已内置）。下单返回 `order / amount / productName / productDesc / callbackUrl / attach`，客户端构造 `PayInfo` 时原样使用。支付结果以 OPPO 服务端回调为准。

## vivo

AppID、CP-ID、支付 AppKey。下单返回含 `vivoSignature` 的全部参数，客户端构造 `VivoPayInfo` 时原样使用（`extuid` 由客户端填登录得到的 openId）。主动查单接口（`queryv2`）按 vivo 服务端文档实现，首次联调时请核对返回字段。

## 小米

AppID、AppSecret。小米的回调地址**不随订单传递**，必须把通道回调地址配置到小米开放平台。下单返回 `cpOrderId / cpUserInfo / amount`。下单时用 `openId` 传入小米 uid 可启用主动查单。

## 模拟通道

用于联调与演示：不请求任何上游；可开启"模拟下单失败"演示故障转移与熔断；支持模拟订阅（后台订阅详情可模拟续费 / 退订 / 恢复 / 到期 / 撤销）与模拟对账单（开启"模拟对账差异"会故意制造三类差异）。在后台订单详情点"模拟支付"，或把下单凭据中的 `body` POST 到回调地址，即可触发与真实回调完全相同的处理链路。**不要绑定到正式渠道。**
